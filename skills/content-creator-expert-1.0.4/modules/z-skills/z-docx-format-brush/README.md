大家好，我是 Ai 学习的老章

今天把一个折磨了我一下午的 Word 格式问题，沉淀成了一个可以永久复用的 Skill，顺手推到了我的 z-skills 开源仓库，这篇文章讲讲全过程

### 事情的起因

事情很简单：我手上有一份项目需求文件，要参照另一个项目的模板，写一份正式的采购文件，Word 格式交付

内容生成这一步，现在随便哪个模型都能干，结构、章节、表格都给你排得明明白白

但我把另一个模型的产出打开一看，血压上来了：

- 中文是宋体、英文是 Calibri，混排得像贴报纸
- 标题顶着一层 pandoc 默认的深蓝色（0F4761，用过 pandoc 的都懂）
- 10 个表格，全部没有边框，白茫茫一片
- 封面就一行普通文字，章节也不分页
- 最离谱的是中文引号，"信用中国"被转成了 ”信用中国“，开闭方向全反

内容 100 分，格式 0 分，这种文件是没法拿去走流程的

### 为什么模型总是搞不定格式

我看了下它的产出方式就明白了：Markdown 底稿 + pandoc 转 docx

pandoc 转出来的 docx，所有文字都不带字体设置，全靠 Body Text、First Paragraph 这些默认样式兜底，中文环境下必翻车

更深层的原因是：**格式参数靠"感觉"是调不齐的**，模型每写一段就设置一次格式，写 500 段就是 500 次独立决策，必然漂移

### 我的方法：格式指纹 + 五层格式刷

核心思路一句话：**格式参数从模板实测出来，收敛到唯一出口应用**

第一步，解剖模板，把每个段落、每个 run 的字体、字号、行距、缩进、对齐全部扒出来，统计众数，形成一份"格式指纹"

这里有个关键认知：**样式表不可信**，中文公文类 docx 几乎都在 run 层直接覆盖字体，样式表里可能还躺着默认值，只信样式表必然刷错，所以指纹必须以实测为准

我从模板扒出来的指纹长这样：

| 元素 | 参数 |
|---|---|
| 正文 | 仿宋、12磅、1.5倍行距、首行缩进2字符 |
| 一二级标题 | 仿宋、15磅、加粗 |
| 封面 | 22磅公司名/项目名 + 26磅文档类型，居中加粗 |
| 表格 | 单线边框、仿宋12磅、表头加粗 |

第二步，按五层顺序把指纹刷上去，顺序很重要：

1. **样式层**：Normal/Heading 1-3 全部改掉，兜住一切继承
2. **段落层**：正文行距缩进、标题字号加粗、章节标题居中分页
3. **封面层**：重做三行式封面
4. **表格层**：补边框、统一字体、表头加粗
5. **文字层**：引号按开闭配对重排

### 三个必踩的坑

写 python-docx 处理中文文档，这三个坑我替你踩完了：

**坑一：中文字体要设两遍**

```python
run.font.name = "仿宋"          # 这行只管西文
rPr.rFonts.set(qn("w:eastAsia"), "仿宋")  # 中文靠这行，漏了必回落宋体
```

**坑二：清颜色要动 XML**

`r.font.color.rgb = None` 清不掉 pandoc 的蓝标题，得从 rPr 里把 `w:color` 元素整个 remove 掉

**坑三：字号换算**

docx 内部存的是 EMU，磅 = EMU ÷ 12700，152400 就是 12 磅，换算错了格式对不上模板还找不到原因

### 沉淀成 Skill

一次性修复只值一杯咖啡，可复用的流程才值钱

我把整套方法沉淀成了 `z-docx-format-brush`，四个脚本覆盖指纹提取、新建、修复和验证：

```shell
# 第一步：解剖模板，输出格式指纹
python3 scripts/extract_fingerprint.py 模板.docx --json fp.json

# 新建文档：结构化内容全部经过 title()/para()/table() 工厂写入
python3 scripts/gen_from_template.py content.json --config fp.json --out 新文档.docx

# 修复文档：把指纹刷到目标文件（不带 --config 走中文公文默认参数）
python3 scripts/apply_format.py 目标.docx --config fp.json

# 最后验证，退出码 0 才算完成
python3 scripts/verify_format.py 目标.docx
```

验证脚本会检查四件事：run 字体是否收敛到指纹规定的几档、表格是否全部有边框、章节是否分页、引号方向是否正确，任何一项不过退出码就是 1

### 实测

拿今天这份 482 段、10 表格的采购文件实测：

修复前：698 个 run 零字体设置、10 个表格无边框、引号全反

修复后跑验证：

```text
[run 字体分布]
  ('仿宋', '仿宋', 12.0) 563
  ('仿宋', '仿宋', 15.0) 84
  ('仿宋', '仿宋', 22.0) 2
  ('仿宋', '仿宋', 26.0) 1
[表格] 共10个，无边框0个
全部通过：字体收敛、无杂色、表格有边框、章节分页、引号正确
```

全文档字体从一团乱麻收敛到四档，就问你爽不爽

### 总结

这个 Skill 适合三类场景：pandoc 或其他模型产出的 docx 格式修复、参照模板从零生成规范 docx、以及单纯想知道两份 docx 格式差异在哪

局限也说清楚：目前指纹覆盖的是中文公文类文档最常用的维度（字体/字号/行距/缩进/边框/分页/引号），页眉页脚、多级编号这些还没进指纹，后面遇到需求再迭代

代码已开源：https://github.com/tjxj/z-skills 里的 `z-docx-format-brush`，拿走不谢
